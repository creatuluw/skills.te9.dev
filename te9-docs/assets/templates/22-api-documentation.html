Section 1

Reference surface

Three tools, one pipeline. render-figure turns Mermaid source into pele layout SVG; clayify restores the Clay ring grammar on top and emits the plate's legend markup; render-figure-video turns a step-player document into an MP4 — driven by the same frame(t) function the browser runs. The registry is the contract at a glance; FIG · 01 draws the chain with the exact flags that bind each edge.

ToolReadsWritesExit codes
render-figure.mjs Mermaid source (.mmd), read as UTF-8 SVG file — or stdout when --output is omitted 0 · 1 · 2 · 3
clayify.mjs pele-rendered SVG + spec JSON clayified SVG (+ <out>.legend.html when the spec has a legend) 0 · 2
render-figure-video.mjs step-player document — FRAME-CORE block + .fig-b.stepplayer SVG MP4 (--out; default assets/experiments/figure-video.mp4) 0 · 1 · 2 · 3 · 4 · 5
Section 2

Shared conventions

One grammar under all three tools. Everything below is behavior of the shared argument reader and the exit-code contract — learn it once and every invocation on this page reads correctly.

ConventionA1

Pairs. Every option is read as the single token following its --name; where a name appears more than once, the first occurrence wins.

ConventionA2

Presence. --test is a boolean: it is detected by presence in argv, never by a value.

ConventionA3

Tolerance. Unknown flags are ignored — only the documented names are read; nothing validates the rest of argv.

ConventionA4

Types. Values arrive as strings; where a parameter is declared numeric, the tool parses it itself — base-10 parseInt for render-figure's width pair, parseFloat for the video tool's --fps and --scale.

Exit-code contract

CodeMeaningRaised by
0Success — including --test with all assertions passingall three tools
1A PeleError rejected the diagram (render-figure), an uncaught runtime error, or --test failuresrender-figure · video
2Usage error or unreadable inputall three tools
3Missing build dependency — pele (render-figure), sharp (video)render-figure · video
4ffmpeg failed to start — is it on PATH?video only
5ffmpeg exited before all frames were writtenvideo only

Output discipline

RuleO1

Channels. Diagnostics go to stderr, logs and progress to stdout; render-figure puts SVG data on stdout only in stdout mode (no --output).

RuleO2

Nothing partial. Both writers render or transform fully in memory before the first write — a rejected source never leaves a half-written file. The two known exceptions are listed where they occur in section 05.

RuleO3

Build-time only. None of these tools is ever a dependency of a finished document (ADR-0005): pele and sharp live in scripts/, never in the HTML.

Section 3

render-figure.mjs

scripts/render-figure.mjs Mermaid source in, layout SVG out — the pele step of the pipeline.

Signature

$ node render-figure.mjs --input diagram.mmd [--output diagram.svg] [--id-prefix fig-1]

Verbatim from the source — this exact line is also the tool's own usage message.

Parameters

NameTypeDefaultBehavior
--inputpathrequired Mermaid source file, read as UTF-8 from the resolved path. Missing flag → usage line on stderr, exit 2. Unreadable file → Cannot read input: …, exit 2.
--outputpathstdout Writes the rendered SVG to this path and logs Wrote <out> (<n> bytes). Omitted, the SVG is written to stdout — pipe it or redirect it.
--id-prefixstringpele default Forwarded to pele as idPrefix — namespaces the SVG's internal element IDs.
--max-widthintegerpele default Forwarded as pele's maxWidth: pele adapts the layout to the width — wraps labels, tightens spacing, switches direction — instead of the finished figure being scaled down afterwards.
--direction-breakpointintegerpele default Forwarded as pele's directionBreakpoint. Parsed only when --max-width is present. The suite's renders pass --max-width 880 --direction-breakpoint 1600.

Example

$ node scripts/render-figure.mjs \ --input assets/figures/22-fig01.mmd \ --output assets/figures/22-fig01.svg \ --max-width 880 --direction-breakpoint 1600
Wrote assets/figures/22-fig01.svg (6797 bytes)

Run for this page — FIG · 01 is that file after clayify. The count is the SVG string's length as the tool reports it. Without --output the same SVG goes to stdout and nothing is logged.

Errors

ExitMessage (stderr)Cause
2 Usage: node render-figure.mjs --input diagram.mmd [--output diagram.svg] [--id-prefix fig-1] --input missing
2 Cannot read input: <reason> input file unreadable (ENOENT and friends)

Section 4

clayify.mjs

scripts/clayify.mjs pele gives layout; clayify restores the Clay ring grammar on top (ADR-0007).

Signature

$ node clayify.mjs --in figure.svg --spec figure.json [--out out.svg]

Verbatim from the source — also the tool's own usage message.

Parameters

NameTypeDefaultBehavior
--inpathrequired The pele-rendered flowchart SVG to transform.
--specpathrequired Spec JSON, schema below. Unreadable file or invalid JSON → the parse error's message on stderr, exit 2.
--outpaththe --in path Where the clayified SVG is written — by default back over the input, in place.

Spec JSON schema

KeyTypeDefaultMeaning
rnumber17 Uniform ring radius — every non-support node becomes a circle of this radius.
nodesobject{} Map of pele node id → presentation. label — mono caps, drawn above the ring (default: the id, uppercased). sub — small label below. fill: true renders a filled clay ring — the deck's klaar convention (filled = here-now).
legendarray— { type, label } entries; glyph type is ring | dot | dbl | fill. Emitted as plate-header markup — not drawn into the SVG (step 4 below).

What it does

Step1

Nodes become uniform clay rings; supporting nodes (pele's support class) become 5px filled gray dots; double circles stay double (r and r−4). Labels sit outside — 11px mono weight 600 above, 10px sub-label below.

Step2

Edges become plain trimmed hairlines between the uniform boundaries — arrowheads stripped (trim: r+2, dots 7).

Step3

Collision-safe canvas — content is translated clear of the legend band (top 44px), the viewBox is extended for label overhang, and the width/height attributes are re-synced to the adapted viewBox (rasterizers read those, not the viewBox).

Step4

Legend → written to <out>.legend.html as one .fig-legend div — the paste-in header markup for the figure plate. This step and its log line run only when the spec has a legend.

Step5

Dark flip — a Clay prefers-color-scheme style block is injected inside the SVG, so the fullscreen new-tab view is Clay-correct without the document's stylesheet.

Example

$ node scripts/clayify.mjs --in assets/figures/22-fig01.svg --spec assets/figures/22-fig01.spec.json
legend markup -> assets/figures/22-fig01.svg.legend.html Clay-ified 8 nodes -> assets/figures/22-fig01.svg

Run for this page — the legend row in FIG · 01's plate header is the pasted .legend.html; FIG · 01 itself is the clayified output.

Errors

ExitMessage (stderr)Cause
2 Usage: node clayify.mjs --in figure.svg --spec figure.json [--out out.svg] --in or --spec missing
2 <error message> input file unreadable, or spec JSON unparseable
Section 5

render-figure-video.mjs

scripts/render-figure-video.mjs the document's frame(t), rasterized and piped to ffmpeg — the video is a function of time.

Requirements: npm i sharp in scripts/ and ffmpeg on PATH. The exporter reads a step-player document, extracts its marked FRAME-CORE — the pure, DOM-free frame function — applies frame(t) to the inline SVG, rasterizes frames with sharp, and pipes raw RGBA into ffmpeg: the exact renderer the browser runs is the renderer that produces the video.

Signature

$ node render-figure-video.mjs --doc doc.html [--out video.mp4] [--fps 25] [--scale 1.5] | --test

Verbatim from the source — also the tool's own usage message.

Parameters

NameTypeDefaultBehavior
--docpathrequired The step-player document. Its FRAME-CORE — the code between /*FRAME-CORE-START*/ and /*/FRAME-CORE-END*/ — must evaluate to { frame, STEPS, DURATION, ALL_IDS }, and its .fig-b.stepplayer div must hold the base SVG. An unreadable path is not guarded: it exits 1 with a stack trace.
--outpathassets/experiments/figure-video.mp4 Output video; the default resolves from the repo root (a sibling of scripts/).
--fpsnumber25 Frame rate — ffmpeg's -r, and the render's sampling step (frame i renders t = i / fps).
--scalenumber1.5 Frame scale — the SVG's pixel size times scale, rounded to even dimensions (yuv420p requires even).
--testflagoff Runs the frame unit tests and exits — no render, no sharp, no ffmpeg. Exit 0 when all eight pass, 1 on any failure.

Render pipeline

Stage1

Extract the FRAME-CORE and evaluate it as a function body; it must return { frame, STEPS, DURATION, ALL_IDS }. Logs FRAME-CORE loaded: <n> steps, <d>s. Missing markers → exit 2.

Stage2

Extract the base SVG from the .fig-b.stepplayer div. Missing → No stepplayer figure found in the document., exit 2.

Stage3

Resolve Clay variables to literal values for the rasterizer — sharp's SVG engine does not resolve var() in presentation attributes (they fall back to black). Surfaces go transparent, fg #141413, muted #87867F, lines #D1CFC5, accent #FE6C2D; unknown variables fall back to their own fallback, else #141413.

Stage4

Apply frame(t) at string level — the same contract as the DOM runtime: per element id, state classes st-future (opacity .06), st-done (.34), st-active (1, stroke-width 3.5px) are swapped in, plus a scoped style block with transition:none for deterministic rasterization.

Stage5

Rasterize and pipe: sharp resizes to the exact frame dims (fit: 'fill'), flattens onto #F0EEE6 — alpha would encode as black in yuv420p — then ensureAlpha() restores RGBA for the pipe declared -pix_fmt rgba. ffmpeg encodes yuv420p with +faststart; writes respect backpressure; a frame-buffer length mismatch throws (exit 1). Progress logs every 25 frames; the run ends Video written: <out>.

Section 6

Error handling

Two layers share the failure duty: pele's PeleError objects carry where and why a diagram was rejected; the exit-code map turns that into scriptable signals. Field names and codes below are read from pele 1.12.0's source — this section is the decoder ring.

PeleError anatomy

FieldCarries
namealways "PeleError" — render-figure branches on it
messagethe human diagnosis, printed verbatim by render-figure
codeone of the four codes below — default "syntax"
type · mermaidTypethe detected diagram type, when detection got that far
line · columnposition in the source — 0 when unknown; render-figure prints at line N, column M (indented two spaces) only when a line is present
snippetthe offending source text

The four codes

CodeRaised when
syntax (default) The Mermaid source doesn't parse. The message names the construct; line/column pinpoint it and snippet carries the offending text.
unsupported-diagram No diagram type detected — No diagram type detected for the given text. — or the detected type is not registered: Diagram type "<type>" is not supported yet.
semantic Parsed, but undrawable — e.g. an xychart with no data: No Plot to render, please provide a plot with some data.
limit Guardrails: the source exceeds the 50,000-character default — Diagram source is longer than the limit of 50000 characters. — or nesting exhausted the stack: Diagram is nested too deeply.

The shared pattern

PatternE1

Name the fix. Guarded failures print the remedy, not just the fault: the dependency lines carry the exact install command (cd scripts && npm install), the usage lines echo the exact invocation, the guards name the missing marker. The known unguarded paths — the video tool's --doc read and its frame-buffer check — exit 1 with a stack trace instead.

PatternE2

Nothing partial. render-figure runs pele.render to completion before its only writeFileSync; clayify transforms the whole string before writing. A rejected render leaves no file behind.

PatternE3

Channels are the contract. Data on stdout only in stdout mode; every diagnostic on stderr; every progress line on stdout; exit codes stable across the toolset — 2 usage/input, 3 dependency, 1 render/runtime, 4–5 the ffmpeg subprocess.
