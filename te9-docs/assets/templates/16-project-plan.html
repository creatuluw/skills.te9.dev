Protocol

One build → one browser gate → approval. Every landing is an autonomous extension: conventions kept, index regenerated, changelog line appended by the building session. Nothing is stored ungated.

Counts only, taken at build time: templates on disk, gates passed, registry entries. The denominator is the frozen 35-type launch taxonomy; the registry trails the directory by design, so the directory is what gets counted.

Dependencies & risks

What waits on what, what could bite

The plan's four real dependencies first — what each step genuinely waits on. Then the four risks that could bend the chain, each paired with the mitigation that holds it. A risk without a named mitigation is a prediction, not a plan.

DEP-01

Every landing waits on its browser review gate. The workflow stores nothing ungated, so the gate cadence is the plan's pace — one build, one gate, by design.

DEP-02

Figure-bearing templates wait on the build-time pipeline — render-figure (pele) then clayify. The pipeline is versioned, and every hardening cycle is a changelog line.

DEP-03

Phase N+1 waits on Phase N's exit criteria. The cluster order is deliberate: the conventions one cluster hardens are the ones the next inherits — the amortization runs forward, never backward.

DEP-04

Nothing waits on index.json. The registry trails the directory by design and regenerates on the next extension — it is a ledger, never a blocker.

Risk Mitigation
R-01 · Gate fatigue
Twenty gates from 15/35 to v1.0.0 — deep into the nine-gate Phase 4 run, reviews could start rubber-stamping, and a rubber-stamped gate is no gate at all.		 Held by
Cluster similarity amortizes the review. Each cluster's first build hardens the conventions its successors reuse, so per-template review effort falls as the cluster runs. The gate inspects the document — plates, dark flip, print, folds — never the count.
R-02 · Convention change mid-cluster
A fix to a shared convention lands mid-cluster — and seems to demand that already-gated templates be reopened and re-reviewed.		 Held by
Cluster-level PATCH applies forward. A convention fix bumps the suite version as PATCH and binds every build from that point on; landed templates stand as gated. The changelog line marks the seam.
R-03 · Figure-pipeline regression
Every figure-bearing template renders through pele + clayify — a regression there would smear bad figures across a whole cluster before anyone notices.		 Held by
The per-template gate catches regressions at the plate before landing — a broken figure cannot pass review — and the pipeline itself is versioned, with its six hardening cycles recorded in the changelog.
R-04 · Scope creep
A session mid-program invents a thirty-sixth type "the suite obviously needs" — and the denominator every count assumes quietly moves.		 Held by
The extension protocol holds new types until v1.0.0. The scope freeze keeps the taxonomy at 35; unlisted types wait — and the protocol's own registration path is exactly where they go after the release.

Counting note, kept honest: the changelog's only unit tests — eight, on the step-player experiment's frame function — cover the parked video export, not the figure pipeline. No test suite is claimed here that the repository does not show; the pipeline's standing guards are the per-template review gate and its versioned, changelogged hardening history.

Governance

The rules the work runs under

Two protocols and one ledger govern every build between this page and v1.0.0. All three are already in force — the suite brief defines them, the changelog shows them working; this plan adds nothing new, it just binds the phases to them.

GOV-01

The gate protocol — one build → one browser gate → approval

Every template is built, opened in the browser and approved before it is stored. Landed means gated — the gate inspects the real document (figure plates, dark-mode flip, print block, folds, the whitelisted script budget), never a summary. A new template bumps the suite version as MINOR; a convention or template fix bumps it as PATCH; the building session appends its own changelog line.

GOV-02

The extension protocol — unlisted types extend the suite the same way

A session needing a type the index does not list builds it to the same conventions — Clay, self-describing content, whitelist compliance, quality gates — saves it to assets/templates/, registers it in index.json, bumps the version and writes its own changelog line; the next session discovers it in the index. During this program the protocol runs under the scope freeze: new types queue until v1.0.0.

SUITE-BRIEF · EXTENSION PROTOCOL · AUTONOMOUS BY DESIGN

GOV-03

The ledger — four marks make a landing

A template is only landed when all four marks exist: the file in assets/templates/, its entry in index.json, the version bump, the changelog line. If any one is missing, the template is not landed — and the next report will count it as what it is: pending.

Why no schedule police: the protocols are deliberately autonomous — the session that builds is the session that registers, bumps and logs, and no calendar governs the phases; the taxonomy does. v1.0.0 is the one gate that spans all five phases, and Phase 5 is that gate, run as work.
