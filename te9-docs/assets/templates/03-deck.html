Discovery findings · what the fieldwork settled

Four signals, one risk

FINDING 01

The suite is its own first subject

Every template's placeholder content documents te9-docs itself. The suite dogfoods its own output, review stays concrete, and the template index doubles as the suite's manual.

Signal
FINDING 02

Hand-built documents drift, then disappear

A bespoke document re-decides type, palette, and structure every time. Nothing registers in the index, nothing is reusable, and the next session starts from zero.

Pain
FINDING 03

Zero webfonts, zero requests, three faces

ui-serif display, system-ui body, ui-monospace micro-labels — no network requests in any document. What a template ships is what a reader opens, years later, offline.

Signal
FINDING 04

Every script is a hole in Clay discipline

Suite documents run zero scripts by default — details folds, :target jumps, hover states. Anything beyond the deck's sanctioned navigation needs the script whitelist, justified at its review gate.

Risk

Current state · one document, five moments

The journey of a produced document

A Document touches five steps between Intake and the storage menu. The instance mechanic is reliable; every step skipped is where drift gets in.

  1. Production run · before any writing

    Intake

    The session asks for the document's goal and acceptance criteria, then states its own recommendation — type plus approach — before the user confirms.

    Pain · no brief, nothing to review against
  2. Production run · the type decision

    Index

    The suite index at assets/templates/index.json is read first and grounds the type decision; two plausible matches get confirmed with the user.

    Pain · skipping it re-invents existing types
  3. Production run · the build

    Instance

    Copy the Template and swap self-describing placeholders for real facts, preserving layout, interactions, and Clay tokens.

    Working well · copy, don't create
  4. Production run · the review gate

    Playback

    The document is shown in the browser and folded with feedback; nothing is built forward until the gate passes.

    Pain · skipping it ships drift to every sibling
  5. Production run · the storage menu

    Store

    Project docs folder, the central collection, preview only — or option four, specify location, which always wins when used.

    Pain · a document needs a home it can be found in

Recommendation · where we'd start

Grow to v1.0 in sibling clusters, never solo

  • →Cluster the build order. Group the thirty-three pending types by similarity — explainers, reports, formal contract types, financial — so gate feedback on one template immediately benefits its neighbors.
  • →Index and version every gate. Each passing template registers in index.json and bumps the suite version — a MINOR for a new type, a PATCH for a fix — with one changelog line each.
  • →Let the suite extend itself. A session needing an unlisted type builds it to the same conventions, registers it, bumps the version, and writes its own changelog line — no asking.
Why no bespoke documents, ever

One-off documents are where consistency dies. Anything a session needs that the suite lacks goes through the extension protocol — Clay conformance, self-describing content, whitelist compliance — and lands in the index where the next session finds it. The launch taxonomy stays the only way in.
