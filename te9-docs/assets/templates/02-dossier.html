TL;DR

Three takeaways

01 · Ownership

Every pattern the suite uses was re-justified and owned as a te9 signature — the verdicts live in the ADRs, not in folklore.

02 · Discipline

Zero scripts by default: folds, :target jumps and build-time figures carry the richness; the deck's navigation script is the only sanctioned exemption.

Theme A

The suite grows without a gatekeeper

Any session that needs an unlisted document type can become an author. The question is whether that autonomy is actually designed in — or merely tolerated.

A1

Growth is a protocol, not a permission slip

High

When a session needs a type the suite doesn't list, it builds the template to convention, registers it in the index, bumps the suite version, and writes its own changelog line. The user discovers the new type in the index next session — nothing waits on an approval.

Theme B

Richness without a single runtime script

Documents need interaction and figures. The suite's answer is mechanisms, not JavaScript — and the receipts show the exemption list is deliberately tiny.

B1

Interaction and figures come from sanctioned mechanisms

High

Progressive disclosure rides details folds and :target jumps; figures are Mermaid rendered to static inline SVG by Pele at build time, in a fenced gray-100 plate. The document a reader receives needs no script to be complete.

Verdict

The design claims hold — ownership, discipline, and autonomy reinforce each other

Keep the architecture as decided. Clean-room ownership (ADR 0001) supplies the stance, Clay discipline (ADR 0002/0004) the quality bar, autonomous extension (ADR 0006) the growth engine. Convert the remaining 33 types through build clusters, with the review gate passing before siblings inherit the feedback. Confidence: Medium–High

What would change our mind

  • A produced Document drifts from Clay — a per-template palette or an unwhitelisted script ships — and no review gate catches it. Discipline would be weaker than the ADRs claim.
  • An autonomously extended template registers without self-describing content or without a suite-version bump — the protocol fails silently, and the index stops being the manual.
  • The suite brief and the index fall out of sync with the templates on disk — the single source of truth is no longer single, and receipts start citing stale facts.
