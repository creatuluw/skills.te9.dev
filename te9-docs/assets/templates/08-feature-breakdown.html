Feature Breakdown

Figures, rendered never drawn.

The feature: every diagram in a te9-docs document comes from the figure pipeline — you write plain Mermaid text, the suite renders it at build time, dresses it in the house grammar, and plates it as a self-contained exhibit. This breakdown takes the pipeline apart: six capabilities, the flow from source to plate, every option, and the limits it honestly has.

Capabilities at a glance

Six things the pipeline does for you

Each capability below is a promise the pipeline makes to every document in the suite. Together they are why a figure in te9-docs never becomes a project of its own.

Capability 01 · Mermaid in

Plain text goes in.

You write the diagram as Mermaid source — versionable, diffable, reviewable text stored next to the document.

Capability 02 · Clay out

The house grammar comes out.

Clayify restores the ring grammar on pele's layout: uniform rings, mono labels outside, hairline edges, no arrowheads.

Capability 03 · Build-time render

Nothing runs at read time.

Rendering happens once, when the document is built. The reader's browser never draws, fetches, or executes anything for a figure.

Capability 04 · Base reading size

Labels never shrink.

Diagrams render at pele's 16px base — the layout adapts to the plate, never the text to the space.

Capability 05 · Fullscreen view

One click, full view.

Every plate header carries a FULLSCREEN pill: the diagram opens in a new tab, Clay-correct, still offline.

Capability 06 · Video export

The same frames as a film.

Step-wise figures export to MP4 through the same renderer the browser runs — sharp for pixels, FFmpeg for encoding.

Limitations

What the pipeline honestly does not do

A feature breakdown that hides its limits is an ad. These three are part of the contract — known, accepted, and revisitable.

Limit 01

No pixel positioning.

Pele decides where nodes sit; clayify adjusts grammar, not geometry. A layout that must be pixel-exact is a hand-authored figure — the one sanctioned exception, noted at the review gate.

Limit 02

No read-time interactivity.

Beyond the fullscreen view, figures are static by design. Step-wise playback exists as an exploration, not a default — zero scripts is the suite's contract.

Limit 03

Video export needs tooling.

The MP4 path requires Node with sharp and FFmpeg on the machine. The document never needs them — only the export step does.
