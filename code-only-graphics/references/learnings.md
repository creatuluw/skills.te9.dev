# Code-Only 3D — Learnings (practice memory)

Accumulated gotchas, heuristics, and better-practice discovered while using this skill. **Read at the start of every build**; append to at the end (see `SKILL.md` → "Recursive improvement"). Newest first. Each entry is a reusable rule, not a one-off note.

## 2,500-tile hex world in one file: texture atlas + merged geometry + instanced prop pools
Scaling from 10 showcase tiles to a 50×50 procedural world (2,500 hexes) dies if each tile is its own textured mesh (draw calls + 2,500 canvases). The architecture that works: **(1) Terrain atlas** — paint all terrain-family top textures ONCE into a 4×4 1024px canvas atlas; per tile, build a `CircleGeometry(R,6)` cap and remap its UVs into its cell (`u = cellX + (0.02 + u*0.96)/N` — the 2% inset stops bilinear bleeding between cells). **(2) Merge everything** — one merged BufferGeometry for all 2,500 caps (with `map:atlas, vertexColors:true`; per-tile variation via a vertex-color tint, not extra textures) + one for all side walls + one for all river ribbons → the whole terrain is ~4 draw calls. Write a tiny manual `mergeGeos` (position/normal/uv/color/index concat) and make ribbons index+uv+color-complete before merging or it crashes on `g.index.array`. **(3) Props via InstancedMesh pools** (`tree/peak/rock/house/shard…`, one pool each, `setColorAt` for per-instance color, overflow-guarded `push`). **(4) Water = one big plane** at sea level under everything — ocean/lake tiles get a below-sea floor top, land tops sit above it; rivers above ground as merged variable-width ribbons (`ribbonVar(pts, widthFn, yFn)` with points at tile centers AND edge midpoints so flow reads continuous). **(5) Sea plane covers whole map** and hides itself under land — no water-edge stitching needed. **(6) Gen pipeline**: fbm elevation × radial falloff (square-max edge metric, `1-edge^2.5` — `edge^3` sinks the whole interior below sea level: 71% ocean) + moisture + row-based temperature minus elevation penalty → classify; rivers traced downhill lowest-neighbor from high-wet sources to sea, stuck traces become lakes. **(7) Tune the classifier OFFLINE in node first** — replicate fbm/hash, print histograms of temp/moist/e on land, fix thresholds there (browser reload cycles are 10× slower). Seed variance is large: run 5 seeds and require only "every family present, land 35–55%". Per-frame cost is trivial; generation of 2,500 tiles + ~15k instances is instant.

## Five houses from one generator: shared life helpers belong in the scaffold
"5 variants of a family" scales past terrain tiles to full buildings: ONE `_gen_houses.mjs` with a shared high-tier scaffold template (35mm camera, sky+fog+rim, `canvasTex`/`M`/`add` helpers) + per-house `{cam, target, sky, fog, hemi, sun, build}` configs → 5 self-contained HTML files. Two additions that paid off: **(1) put the LIFE system in the shared scaffold**, not per house — global `swayables`/`flickers`/`smokeMat` arrays with `sway(group,phase,amp)`, `flicker(mat,base)` and `makeSmoke(x,y,z)` helpers; every house then just calls them and the shared animate loop drives all motion. **(2) A shared `makeGrassTex(palette...)`** — the v2 grass draw with parameters, so each house tints its lawn (olive, sandy, dusk) from one function. Verification loop that caught everything: `node --check` each extracted `<script type="module">` body, serve via python http.server, Python-playwright screenshot sweep (pageerror/console-error listeners + unique-color-count on the PNGs to catch blank renders — no vision model needed). New geometry idioms captured in `techniques.md §11`: cone-scaled hip roof, Shape+absarc arch, 4-sided-cylinder tapered column, canvas-frond palm, gradient barrel tiles. *(From the 5-house style set: Craftsman / MCM / Colonial / Mediterranean / Victorian.)*

## High-fidelity "hero" builds = brief first, then layered passes, with a material library
For "make it look like a Pixar render" requests, one-shot part lists fall flat. The reliable sequence (validated on the storybook cottage v2, a ~4× quality jump over v1 at similar part count):
**(1) Brief before code** — subject/style/view/mood + materials map + dressing + atmosphere + life. Declare a fidelity tier (hero-render / midground / background); it sets how many passes the build deserves. **(2) Build in passes**: silhouette → form → **material library** → dressing → atmosphere → life. **(3) The "asset tier" for code-only is a canvas texture library** — one `canvasTex(w,h,draw,rx,ry)` helper (SRGB + RepeatWrapping + repeat) generating clapboard siding, scalloped shingles, river stone, panelled door, painted grass. Real materials do more for perceived fidelity than extra geometry. **(4) Atmosphere pass is cheap and huge**: vertical-gradient sky as `scene.background` CanvasTexture + `THREE.Fog` matched to the horizon colour + a cool rim DirectionalLight behind the warm key — instant "golden hour". **(5) Life pass**: candle-flicker windows (`emissive = 1 + 0.25·sin(slow) + 0.08·sin(fast)`), swaying tree crown group, a butterfly on a Lissajous path with flapping wing pivots. **(6) Critic pass** (SKILL.md step 6): score/category/observation/repair, fix high-severity, stop. Also: **Pixar-style means smooth shading, NOT flatShading** (flat is retro/gamey; soft round forms + warm palette + PCF soft shadows + ACES 1.15 is the look), and use a **35mm PerspectiveCamera** for hero shots, not iso ortho. **(7) Cylinder material groups [side,top,bottom] apply to the ground disc too** — painted grass on top, dirt colour on the sides.

## ExtrudeGeometry UVs are in shape/world units, not 0–1
An `ExtrudeGeometry` of a triangle spanning x∈[−3,3] gets UVs equal to the raw coordinates (u from −3 to 3). With `RepeatWrapping` this works in your favour: **one texture tile ≈ one world unit**, so a shingle canvas with 4 courses per tile = 0.25-unit courses — no UV rescaling, just size the drawing inside the tile. *(Both learnings from house.html → house-v2.html.)*

## N terrain variants from one build: config-driven generator script
When a request is "5 tiles of the same family, different biome", don't write 5 near-identical HTML files by hand — write ONE `_gen_tiles.mjs` next to the output folder holding the shared scaffold as a template literal plus a per-tile config `{ params, colorFn, extraBuild }`, run `node _gen_tiles.mjs`, keep the script as the single source of truth for tweaks. Porting the `webgpu_tsl_procedural_terrain` TSL elevation to JS is a 6-liner: `w=(fbm(p*freq*warpFreq)-0.5)*2*warpStr; p+=w;` then octaves `e += (fbm(p*freq*i*2 + i*9.87)-0.5)*2/((i+1)*2)` and finish `sign(e)*e²*strength`. Its colour bands port as `step`→`if` on height/slope with the exact palette sand `#ffe894` / grass `#85d534` / rock `#bfbd8d` / snow `#ffffff` / water `#4db2ff`. "Still" tile = render loop with `controls.update()` only (no autoRotate, no animated parts) — damping needs the loop, nothing moves. *(From the 5-tile terrain set in game-assets/.)*

## "Flat plane + painted texture beats displacement" applies to GROUND, not mountains
The earlier rule (don't displace a grid floor — bake unevenness into a CanvasTexture) is correct for *near-flat* terrain where relief is sub-detail. A **mountain tile is the exception**: the silhouette IS the content, so real displaced geometry with `flatShading:true` is required — the painted-texture approach can't produce a summit profile against the sky. The full pattern (ridged fbm `1-|2n-1|`, hex-slab clamp, `(1-rim²)` falloff to weld to the prism, ragged vertex-colour snowline) is now in `techniques.md §9`. Companion rule inside: on displaced mountains flat shading is desirable (crag), on flat ground it's a bug (shows triangulation). *(From mountain-hex.html.)*

## Instanced crop field that grows, ripens, and is harvestable
A farmable wheat/grain tile in three cheap moves. **(1) Grow by scaling, not moving.** Base-anchor the `InstancedMesh` geometry with `geo.translate(0, h/2, 0)` so its base sits at y=0; then each frame `dummy.scale.y = ease(growth)` makes every sheaf sprout upward from the soil while `dummy.position.y` stays constant. **(2) Ripen with ONE shared material.** All stalks ripen together, so skip per-instance colour — `mat.color.copy(baseGreen).lerp(ripeGold, ripeness)` (ripeness 0→1 across the last ~40% of growth) turns the field green→gold for free. Add per-instance height jitter (`0.85 + 0.3*((k*13)%7)/7`) so a uniform grid doesn't read robotic. **(3) Harvest via the underlying terrain face, not the crop.** Put the soil/wheat overlays ABOVE the tile face but keep them OUT of the raycast `pickables` array — the click resolves to the grass face below; branch on that face's `userData` (same q,r as the acre) to fire the harvest (reset `growth=0`, add yield) instead of normal selection. The harvest-me affordance is the existing **breathing gold hex ring** (`opacity = ripe ? 0.3+p*0.5 : 0`), which doubles as the ripe indicator. Growth loop: `growth += dt/22`, ripe at ≥1, holds ripe until clicked. *(From grain-acre.html.)*

## Realistic procedural rock = noise-displaced icosahedron + baked vertex colour
For natural boulders / stones / mountain spires, skip `DodecahedronGeometry` (reads toy-like) and `ConeGeometry` (reads pyramidal). Take `IcosahedronGeometry(r, detail 2–3)` and push each vertex along its normal by a low-frequency **3D value-noise fbm** sample — `d=(fbm3(x,y,z)-0.5); v += normal*d*r*0.55` → a lumpy, irregular silhouette. Bake **per-vertex colour** for the realism: granite base; lerp toward dark in low/down areas (fake AO keyed off normalized height `h=(y/(r*1.25)+1)/2`); lerp toward light on the top facets (sun-lit); rare moss/lichen where a `hash3` threshold passes; small per-vertex HSL value jitter. Material `vertexColors:true, flatShading:true, roughness≈0.96` — flat shading lights each displaced facet differently, which is the fractured-stone read. Then `computeBoundingBox()` + `translate(0,-min.y,0)` so the rock's base rests on y=0 regardless of displacement (now scale/rotate freely). Reuse ONE shared material + a few seeded geometry **variants** scattered as individual meshes for shape variety (InstancedMesh can't vary shape per instance). The same builder serves boulders AND peaks — peaks just scale y tall and taper x/z slightly. 3D value noise is a 3-axis trilinear interpolation of an integer-hash (8 corners), fbm = 4 octaves of it. *(From the mountain/rocky tile: the original flat dodecahedron boulders looked like dice; this reads as eroded granite.)*

## Mineable resource node = pulsing emissive + breathing hex ring
For a 4X/strategy resource tile (mineable stone/ore/wood/gold), the universal "harvest me" affordance is: an **emissive material whose `emissiveIntensity` pulses on a slow sine** (the crystal/ore itself) **PLUS a flat hex `RingGeometry(r1,r2,6)` whose `opacity` breathes in sync** sitting on the floor around the node. Drive both from one value — `p = 0.5+0.5*Math.sin(t*0.004)`; `crystalMat.emissiveIntensity = 0.5 + p*0.9` and `ring.material.opacity = 0.25 + p*0.4` — so they read as a single living hotspot. The pulsing-emissive and selection-ring snippets already exist separately in techniques.md; the reusable insight is **pairing them as the resource-tile idiom**. Add a gentle `vein.position.y` bob + slow `vein.rotation.y` drift for life. *(From the mountain/rocky mineable tile.)*

## A 5-sided cone makes a craggy mountain peak (6 reads too regular)
`new THREE.ConeGeometry(r, h, 5)` with `flatShading:true` gives an irregular, off-axis silhouette that reads as a craggy rock summit; `6` radial segments read as a too-regular pyramid. Stack a narrow white cone on top for the snow cap, and build the tile from 3 peaks of varying height — 1 tall summit + 2 smaller spurs offset to opposite sides — to sell a ridge rather than a single nipple. *(From the mountain/rocky mineable tile.)*

## Verify generated module JS with node --check before serving
Extract the `<script type="module">` body to a `.mjs` and run `node --check` — it catches syntax/brace errors that serving-over-http won't (a `LineLoop` handed a points array; a missing `}` closing a `switch` case both slipped past the raw brace count and only crashed at runtime). A 5-second check that beats "open browser, see console error". *(From the hex map.)*

## Parent selection overlays to the transformed container
If the map group rotates (turntable) or moves, a selection ring added to `scene` drifts off its tile. Add it as a child of the map group so it transforms with the tiles. General rule: any marker that must track an object under a parent transform goes inside that parent, not the scene. *(From the hex map turntable.)*

## Don't flatShade a displaced grid terrain — it bakes the triangulation into the shading
`flatShading:true` gives every triangle its own face normal, ignoring shared vertex normals. On a smoothly-displaced grid floor that means ~thousands of facets, each lit-or-dark by face normal, with hard edges between them — so the underlying **triangulation shows through as angle-dependent green/dark rectangles and ridges** as you orbit. (Shadows depend on the *light*; if a pattern changes with your *viewing* angle, it's shading, not shadows.) Two fixes, in order of strength: (1) smooth-shade — `flatShading:false` + `computeVertexNormals()` hides the triangulation and is enough for *gentle* displacement; (2) **for stylized board/iso terrain that must look clean from every angle, skip displacement entirely and use a FLAT plane + a painted `CanvasTexture`** (base fill + soft-blob colour layers + fine speckle) — the "uneven" read is baked into the texture so it never shifts with the view. The displaced grid kept producing residual angle artifacts even when smooth-shaded; switching to flat+painted-texture (the approach `code-examples/scenes/hex-map.html` uses) eliminated them. *(From the Catan forest hex.)*

## A grid culled to a polygon leaves a jagged edge — clamp boundary verts instead of culling
Building a displaced terrain/floor as a square grid and **culling cells whose centroid is outside the target polygon** (hex, circle, etc.) leaves a **stair-stepped boundary** that does NOT align with a clean polygonal tile edge. Where the grid pokes past the tile wall you see dark undersides; where it falls short you see gaps to a dark cap — viewed from the side these read as **dark notches/rectangles marching along the rim**. Fix: **don't cull — clamp.** Snap every outside grid vertex onto the polygon boundary (for a flat-top hex that's 3 slabs: `|x|≤R`, `|z|≤R√3/2`, `√3|x|+|z|≤√3R`), set those boundary verts to base height, and emit the **full grid**. The mesh edge then coincides exactly with the tile rim — no overhangs, no gaps. *(From the Catan forest hex — dark rectangles on the tile sides at eye height were the jagged floor boundary vs the clean hex prism edge.)*

## Ground catches shadows but shouldn't cast; vertical walls shouldn't receive
For terrain / board-tile scenes, mind which surfaces cast vs receive. Set the **ground/floor mesh `receiveShadow=true` but `castShadow=false`** (a near-horizontal ground projecting a shadow does nothing useful and lands it on adjacent vertical walls), and set **vertical walls (`tile.receiveShadow=false`) to NOT receive projected shadows** — otherwise the elevated ground + tree shadows paint solid black patches on the tile's side faces (walls that can't sensibly catch a top-down shadow). Trees: `castShadow=true, receiveShadow=false`. Also add `sun.shadow.normalBias ≈ 0.03` (not just depth `bias`) to kill acne on flat-shaded faceted walls. *(From the Catan forest hex — black patches on the hex sides were the floor/tree shadows projected onto the vertical prism walls.)*

## CylinderGeometry has 3 material groups [side, top, bottom] — great for tokens/coins/tiles
`new Mesh(cylinderGeo, [sideMat, topMat, bottomMat])`. Three.js assigns group indices 0=side, 1=top(cap), 2=bottom. Use it to put a different face on the cap than the edge: a **number chit** (cream sides + canvas-drawn number on top), a chunky **board tile** (dark sides + grass-textured top), a coin, a poker chip. The cap's UVs map the circle into the central unit circle (center=(0.5,0.5), radius 0.5 in UV), so draw your art within ~0.5 of the canvas center — anything in the corners is clipped. Catan-style number token: `CylinderGeometry(r,r,h,36)` + a canvas with a bold number and probability pips (`pips = 6 - Math.abs(7 - num)` → 6 and 8 get 5 pips, the red ones), lying flat on the tile. *(From the Catan forest hex.)*

## LineLoop / Line / LineSegments take a BufferGeometry, not a points array
`new THREE.LineLoop(pointsArray, material)` throws `Cannot convert undefined or null to object` inside `updateMorphTargets` — these constructors expect a `BufferGeometry` first arg. Build one from points: `new THREE.BufferGeometry().setFromPoints(vec3Array)`, then pass that. *(From the hex-map grid lines.)*

## RingGeometry with thetaSegments=6 makes a hex ring
`new THREE.RingGeometry(inner, outer, 6)` is a flat hexagonal ring — perfect for a hex-tile selection highlight. Lay it flat with `rotation.x = -Math.PI/2` and pulse its opacity. Generalises: any n-gon ring via `RingGeometry(r1, r2, n)`. **Orientation:** the 6-segment ring is flat-top by default (vertices at 0°/60°/…); for a **pointy-top** tile add `rotation.z = Math.PI/6` (+30°) so the ring's points align with the hex's points. **Exact-match alternative:** build the ring as a `Shape` (outer pointy-top hex) with an inner pointy-top hex `Path` hole using the *same* vertex angles (`60*i+30`) as the tile's `FACE` geometry — it then aligns with zero rotation guesswork and no sub-pixel gaps, handy when a ring must sit perfectly inside an existing pointy-top `ShapeGeometry` tile. *(Hex ring + pointy-top offset from the hex map, the mountain/rocky mineable tile, and grain-acre.html's harvest ring.)*

## A hex tile is CylinderGeometry(...,6); TILE_R < SIZE leaves gaps
`CylinderGeometry(r, r, h, 6)` is a hexagonal prism — flat-top by default (rotate `π/6` for pointy-top). Space tiles with flat-top axial math `x = 1.5*SIZE*q`, `z = √3*SIZE*(r + q/2)`; make the geometry radius (`TILE_R`) slightly smaller than the spacing (`SIZE`) so tiles read as separate board pieces.

## For partial arcs use Shape+absarc, not RingGeometry
`THREE.RingGeometry` only makes a full ring (no `thetaStart`/`thetaLength`). For a penalty "D", corner arc, or any partial arc, build an annular sector with a `THREE.Shape` + two `.absarc()` calls (outer forward, inner back) → `ShapeGeometry`. The same helper covers full circles too. *(From the football pitch.)*

## 2D top-down uses MeshBasicMaterial (unlit) — skip the lights
In a top-down 2D scene every material is `MeshBasicMaterial` (flat color, ignores lights) and you add **no lights**. Control layering with small `z` offsets, not 3D depth. The 3D iso scaffold (sun + hemisphere + shadows) is wrong for 2D.

## Rolling is invisible on a smooth wheel
A plain `CylinderGeometry` wheel is rotationally symmetric around its axle, so spinning it produces no visible change. To show motion, spin a part that breaks symmetry: a **toothed drive sprocket**, a tread/grouser scroll, a marked hub, or spokes. *(From the Mammoth Tank — spin the sprocket, not the road wheels.)*

## A flat textured box does not read as a tank track
A `BoxGeometry` with a canvas tread texture looks like a painted box, not running gear. Build tracks as real 3D geometry: an **extruded stadium-ring band** wrapping road wheels + a toothed sprocket + idler + return rollers + grouser cleats (see `techniques.md §8`). The silhouette is what sells "tank" — texture alone never does.

## ES-module importmaps are blocked on file:// — serve over http
Opening a generated `.html` via `file://` fails silently (browsers block module scripts under CORS). Always serve the folder (`python -m http.server`) and open over `http://`. Confirm HTTP 200 before declaring done.

## Use a material array to texture only the sides of a box
`new Mesh(geometry, [side, side, cap, cap, side, side])` — Three.js box face order is `[+x,-x,+y,-y,+z,-z]`. Put the window/facade canvas texture on the 4 side faces and a plain material on top/bottom. *(From the skyscraper / command-center recipe.)*

## init_skill.py needs PYTHONUTF8=1 on Windows
The skill-creator's `init_skill.py` prints emoji and crashes under cp1252. Run it as `PYTHONUTF8=1 PYTHONIOENCODING=utf-8 uv run scripts/init_skill.py ...`. Only relevant when re-initializing or iterating the skill itself.

## Standalone mountain tiles beat merged ridges when tiles must read as board pieces
Two valid mountain styles for hex worlds: **merged ridge chains** (spine BFS + one continuous mesh per chain — reads as a real mountain range) vs **standalone tiles** (every mountain tile independently rolls 1–2 peaks + spur + rocks + snow + rare watchtower/mine; scale `0.85–1.4 × (0.82+elev·0.055)` so summit height tracks the tile's level). Pick by intent: worldmap realism → ridges; board-game/tabletop where each tile is a distinct place → standalone. When going standalone, delete the spine/ridge code entirely (keep only a per-tile `fringe = any neighbor of a different family` flag for rock color variation and volcanic-vent selection — it was previously computed inside the cluster pass). Stray "boulder spur" peaks at ~12% keep clusters from looking stamped. *(From hex-tiles-gen-map.html.)*

## Cinematic tier post stack: bloom → grade → OutputPass, controls freed after intro dolly
Cinematic resolution on Three 0.160: `EffectComposer(renderer, WebGLRenderTarget(w,h,{samples:4, type:HalfFloatType}))` → `RenderPass` → `UnrealBloomPass(strength≈0.28, radius 0.55, threshold 0.85)` → custom `ShaderPass` grade (warm lift `mix(c, c*vec3(1.045,1.0,0.945), 0.55)`, cool floor-lift by `1-smoothstep(0,0.5,vUv.y)`, vignette `1-smoothstep(0.42,0.98,d)*0.34`, animated hash grain ±0.028) → **`OutputPass()` last** (it applies tone mapping + sRGB; grading before it keeps values in scene-linear). Intro camera dolly: start with `ctrl.enabled=false`, lerp `introFrom→introTo` on cubic ease for ~3s, then hand over — keeps autoRotate from fighting the dolly. For "frame the land" on procedural worlds, set the default `controls.target` and dolly endpoint to the **land centroid** (mean of land tile positions), not world origin — otherwise the hero shot is 55% ocean. *(From hex-tiles-gen-map.html, hero+cinematic tier.)*
