Motion & Animation

Motion brings the interface to life — guiding attention, communicating state changes, and creating a sense of polish. Every animation in this system shares a common easing curve and timing scale so that movements feel unified and intentional rather than random or jarring.

Shared Easing & Durations
Token Value Usage
--ease-spring cubic-bezier(0.2, 0.8, 0.2, 1) All enter/exit curves
--duration-fast 200ms Micro-interactions (toggle, checkbox)
--duration-normal 300ms Standard transitions (hover, focus)
--duration-slow 500ms Overlay transitions (modal, dropdown)
--duration-slower 800ms Page-level reveals, hero entrance

1. Fade-In Up — Hero Entrance

Elements translate 30px upward while fading from transparent to opaque. Staggered delays create a cinematic reveal sequence that leads the eye through content hierarchy. Used for hero text, labels, CTAs, and any first-impression content.

Label — delay-1
Heading — delay-2
Body text fades in third — delay-3
@keyframes fadeInUp { from { opacity: 0; transform: translateY(30px); } to { opacity: 1; transform: translateY(0); } }

.animate-fade-in-up { animation: fadeInUp 0.8s var(--ease-spring) forwards; opacity: 0; }
.delay-1 { animation-delay: 0.1s; } through .delay-5 { animation-delay: 0.7s; }

2. Stagger Children

Automatically applies the fade-in-up animation to every direct child with incrementing delays (70ms apart). Ideal for card grids, tag lists, and any collection of items that should appear to cascade into view rather than pop in simultaneously.

3. Section Reveal on Scroll

Sections start invisible and translated 30px down, then animate into view when they enter the viewport via IntersectionObserver. Once revealed, the observer disconnects so the animation never repeats. This is the primary page-scroll animation.

This box fades in
Simulates a section-reveal triggered by IntersectionObserver
.section-reveal { opacity: 0; transform: translateY(30px); transition: opacity var(--duration-slower) var(--ease-spring), transform var(--duration-slower) var(--ease-spring); }
.section-reveal.revealed { opacity: 1; transform: translateY(0); }

4. Nav Link Underline

A pseudo-element underline grows from left to right on hover, creating a subtle but satisfying feedback loop. The width transition uses the standard duration and a linear easing for a clean mechanical feel.

Hover me And me Also me
.nav-link::after { content: ""; position: absolute; bottom: -2px; left: 0; width: 0; height: 1px; background: var(--color-brand-dark); transition: width var(--duration-normal) ease; }
.nav-link:hover::after { width: 100%; }

5. Image Hover — Scale & Reveal

Images gently scale up (1.04x) on hover while an overlay fades in with backdrop blur. The slow duration (800ms) and spring easing make the effect feel organic rather than mechanical. Used for portfolio cards, gallery items, and feature images.

6. Modal — Slide Up with Backdrop

The backdrop fades from transparent to a blurred dark overlay while the modal content slides up 20px and fades in. The two-phase transition (opacity for the backdrop, transform + opacity for content) creates a layered sense of depth.

.modal-overlay { opacity: 0; visibility: hidden; transition: opacity var(--duration-normal) ease; }
.modal-overlay.active { opacity: 1; visibility: visible; }
.modal { transform: translateY(20px); transition: transform var(--duration-normal) var(--ease-spring); }
.modal-overlay.active .modal { transform: translateY(0); }

7. Tag Pill Hover

Tag pills invert their colors on hover — light background becomes dark, dark text becomes white. The all property transition ensures both background and color animate in sync for a smooth, unified state change.

Brand Identity Editorial Typography Motion
.tag-pill { transition: all var(--duration-normal) ease; cursor: pointer; }
.tag-pill:hover { background: var(--color-brand-dark); color: #fff; }

8. Scroll Bounce Indicator

A subtle vertical bounce animation (6px) that loops every 2 seconds, drawing the user's eye downward. Used sparingly for scroll-hint arrows and chevrons. The infinite loop and ease-in-out timing keep it gentle and non-distracting.

Scroll
@keyframes scrollBounce { 0%, 100% { transform: translateY(0); } 50% { transform: translateY(6px); } }
.scroll-indicator { animation: scrollBounce 2s ease-in-out infinite; }

9. Timeline Line Draw

A vertical line animates its height from 0 to 100%, creating the illusion of being drawn on-screen. Triggered by IntersectionObserver when the timeline section enters the viewport. The spring easing gives it a natural deceleration.

10. Reduced Motion

All animations respect the prefers-reduced-motion media query. When the user has enabled reduced motion in their OS settings, every keyframe animation is disabled and elements are shown in their final state immediately. This is a non-negotiable accessibility requirement.

@media (prefers-reduced-motion: reduce) {
  .section-reveal { opacity: 1; transform: none; transition: none; }
  .animate-fade-in-up { animation: none; opacity: 1; transform: none; }
  .stagger-in > * { animation: none; opacity: 1; transform: none; }
  .timeline-line { animation: none; height: 100%; }
  .scroll-indicator { animation: none; }
}

Design Tokens

Design tokens are the single source of truth for visual decisions. They exist in three layers — Global, Semantic, and Component — so that raw values, meaningful aliases, and scoped overrides each live at the right level of abstraction.

Global Tokens

Raw, primitive values that serve as the palette from which all other tokens derive. These are never used directly in components — they feed into semantic and component tokens instead.

Token Value
--color-accent #ED722E
--color-brand-dark #181617
--color-brand-muted #71717A
--color-brand-light #A1A1AA
--color-brand-bg #F5F5F5

Semantic Tokens

Alias tokens that map global values to meaningful names, describing the purpose rather than the value. When the palette changes, only the mapping needs to update — components stay untouched.

Token Maps To
--surface-primary --color-brand-bg
--text-primary --color-brand-dark
--text-secondary --color-brand-muted
--text-tertiary --color-brand-light

Component Tokens

Component-scoped tokens that allow individual components to be themed without side effects. Each component owns its tokens, making overrides predictable and isolated.

Component Token
Button --button-bg, --button-text
Card --card-bg, --card-border
Input --input-border, --input-focus

Reusable solutions

Patterns are proven solutions to recurring interface problems. They combine foundations and components into ready-made layouts that solve real user tasks — so teams don't reinvent the wheel for forms, navigation, and state management.

Grid & Layout

Our grid is built on an 8px base unit. All spacing, sizing, and breakpoints derive from multiples of 8 — creating a consistent visual rhythm across every screen size and density.

Base Unit: 8px
8px = 1x
16px = 2x
24px = 3x
32px = 4x
Breakpoints
Breakpoint Width Columns Margin
Mobile < 640px 4 24px
Tablet 640–1023px 8 32px
Desktop 1024–1399px 12 40px
Wide ≥ 1400px 12 auto
Rules
1
Gutters are always 8px or 16px (1x or 2x base unit). Never arbitrary values.
2
Page margin scales by breakpoint — 24px → 32px → 40px. Content never touches the edge.
3
Max content width is 1400px, centered. Beyond that, margins grow.
4
All component padding, gaps, and margins must be a multiple of the 8px base unit. Half-step (4px) allowed for icon alignment only.
5
Use border-box sizing. Borders draw inward — never let a 1px border break your 8px rhythm.

Guidelines and requirements

Rules are the non-negotiable constraints that keep the system consistent. They cover how space communicates hierarchy, how layouts adapt to different content needs, accessibility requirements, interaction states, and implementation standards.

Spatial Hierarchy

Space communicates importance. Dense spacing signals related content; generous spacing signals separation. Our hierarchy moves from tight micro-adjustments inside components to spacious breathing room between major page sections.

Micro (4px) — Inside components
Icon-to-label gaps, inline badge padding, checkbox-to-text spacing.
Tight (8px) — Between sibling elements
Buttons in a row, list items, form fields in a group, tags in a set.
Standard (16px) — Within sections
Card internal padding, label-to-input gap, paragraph spacing, component guts.
Comfortable (24px) — Between sections
Between form groups, card-to-card in a grid, header to content.
Spacious (48px–80px) — Page sections
Between major page sections. The whitespace that gives the page room to breathe.

Without a spatial hierarchy, every gap looks arbitrary. Users perceive inconsistent spacing as untrustworthy or "cheap." A predictable rhythm — where related things are close and separate things have room — builds visual confidence. It also means any designer or developer can pick up where another left off without guessing.

Layout Composition

Not all content should behave the same way at different screen sizes. Three layout strategies — responsive, adaptive, and strict — are chosen based on what the user needs from the content, not by personal preference.

Responsive
Fluid columns
Content scales with the viewport. Column count stays fixed, width stretches. Use for: editorial pages, dashboards, hero sections.
Adaptive
Fixed boxes that wrap
Items have a fixed size and tile across. Count grows with width. Use for: card grids, icon toolbars, product listings.
Strict
No flex, scroll instead
Fixed dimensions that don't scale. Horizontal scroll below a threshold. Use for: data tables, code blocks, complex forms.
Does the user need to see more items or more content per item?
→ More items → Adaptive (fixed boxes that wrap)
→ More content → Responsive (fluid columns)

Would shrinking this below a certain size harm legibility?
→ Yes → Strict (scroll at breakpoint)
→ No → Responsive

Accessibility

Every implementation must meet WCAG 2.1 Level AA minimum. Accessibility is not optional — it's a baseline requirement that ensures the interface works for everyone, regardless of ability or assistive technology.

  • Contrast ratio: 4.5:1 for normal text, 3:1 for large text
  • Keyboard navigation for all interactive elements
  • Focus-visible rings for keyboard users
  • Skip navigation links
  • Reduced motion support via media query
  • Semantic HTML structure

Interaction States

Every interactive component must define five states so users always know what they can do, what they're doing, and what just happened. Missing states create confusion; consistent states build confidence.

  • Default — resting appearance
  • Hover — transition: var(--duration-normal)
  • Focus — outline, not box-shadow alone
  • Active/pressed — visual feedback on interaction
  • Disabled — opacity: 0.5, cursor: not-allowed

Usage Guidelines

Implementation standards that keep the codebase clean, maintainable, and free of surprises. These aren't suggestions — they're the contract between design and engineering.

  • Use vanilla CSS with custom properties in :root
  • Semantic class names only (no utility strings)
  • Zero external CSS dependencies
  • Mobile-first responsive approach
  • Longhand padding for sections (never shorthand with .page-container)
  • 60-30-10 color rule for visual balance

Design Principles

The twelve core principles that guide every visual and interaction decision in this system. They provide a shared vocabulary for evaluating design choices and ensure that every screen communicates with clarity and purpose.

Balance
Why: Stability & structure
Purpose: Distribute visual weight evenly
Goals: Symmetrical or asymmetrical equilibrium
Align elements on an invisible axis; pair heavy text blocks with ample white space to prevent visual tilt.
Contrast
Why: Visual interest & hierarchy
Purpose: Make elements distinct
Goals: Clear differentiation through opposition
Pair light and dark, large and small, bold and thin to guide the eye and establish reading order.
Emphasis
Why: Directs user attention
Purpose: Create a single focal point
Goals: One clear priority per view
Use size, color, or position to make CTAs and key info unmissable — only one hero per screen.
Movement
Why: Controls content consumption
Purpose: Create a visual path
Goals: Natural top-to-bottom flow
Use spacing, arrows, and progressive disclosure to lead users through content in a logical sequence.
Pattern
Why: Predictability & reduced cognitive load
Purpose: Visual consistency
Goals: Reusable structural motifs
Repeat button styles, card layouts, and spacing rhythms across pages so users learn once, apply everywhere.
Proportion
Why: Communicates hierarchy
Purpose: Harmonious size relationships
Goals: Elements sized by importance
Headings larger than body; icons proportional to text; containers sized to their content, not the viewport.
Repetition
Why: Reinforces brand identity
Purpose: Unify through recurring elements
Goals: Same styles everywhere
Reuse token values everywhere; never introduce new styles for one-off cases without updating the system.
Rhythm
Why: Predictable visual tempo
Purpose: Consistent spacing intervals
Goals: Even, natural intervals
Apply the 8px grid strictly; equal gaps between cards; consistent section padding across all pages.
Unity
Why: Cohesive visual whole
Purpose: All elements belong together
Goals: One system, one voice
Use shared tokens, consistent borders, and matching radii so every component feels like part of the same product.
Hierarchy
Why: Guides user understanding
Purpose: Establish clear levels of importance
Goals: Obvious visual priority at every level
Use size, weight, color, and position to create a clear reading order — users should instantly know where to look first, second, and third.
Variety
Why: Prevents monotony & visual fatigue
Purpose: Introduce controlled diversity
Goals: Thoughtful contrast within consistency
Alternate card orientations, mix image and text blocks, vary component density — keep layouts engaging without breaking the system.
White Space
Why: Content needs room to breathe
Purpose: Separate & group by absence
Goals: Generous, readable layouts
Don't fill every pixel. Use spacing tokens to create visual breathing room — margins are not wasted space.
